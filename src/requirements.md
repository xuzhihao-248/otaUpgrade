# OTA 烧录脚本 — 需求文档

> 版本: v0.2 | 日期: 2026-05-22

---

## 1. 项目背景

当前项目中存在两套独立的 OTA 升级脚本：

- **`ota_alone.py`**：GUI 版本（tkinter），支持一键完整升级 + 单独升级 MCU / Switch / SoC，使用**直接上传固件文件**的方式。
- **`all.py`**：命令行版本，仅支持完整升级流程，使用**上传 zip 压缩包 → 远程解压**的方式。

两套脚本的核心逻辑相同（SSH 连接 → 上传固件 → 远程执行升级命令 → 重启 → 版本校验），但代码重复、入口分离，不利于维护与使用。本次需求是将两者**合并为一个统一脚本**，同时支持 CLI 与 GUI 两种运行模式，并允许用户在每次运行时**手动确认/修改配置参数**。

---

## 2. 核心目标

- 将 CLI 与 GUI 合并为**单一入口脚本**，通过命令行参数切换模式（默认 GUI）。
- 每次运行先进入**配置确认环节**，读取 `config.json` 的默认值，用户可手动修改所有参数。
- 同时支持两种固件上传方式，**根据用户选择的文件类型自动判断**：选择 `.zip` 文件 → 压缩包上传 + 远程解压（原 all 方式）；选择单个固件文件 → 直接上传（原 ota_alone 方式）。
- 保留全部升级功能：一键完整升级、单独升级 MCU、单独升级 Switch、单独升级 SoC。
- 降低使用门槛，无需任何命令行经验即可通过 GUI 完成 OTA 升级。

---

## 3. 运行模式

### 3.1 模式选择

| 启动方式 | 行为 |
|----------|------|
| `python ota_tool.py` | 默认启动 GUI 模式 |
| `python ota_tool.py --cli` | 启动命令行模式 |
| `python ota_tool.py --gui` | 显式指定 GUI 模式 |

### 3.2 GUI 模式

- 基于 tkinter 实现（沿用现有 `ota_alone.py` 的技术栈）。
- 启动后**先弹出配置窗口**，确认配置后再进入主升级界面。
- 所有升级任务在后台线程执行，不阻塞 UI。

### 3.3 CLI 模式

- 纯终端交互，使用 `print` / `input` 完成配置确认与升级过程。
- 所有输出实时打印，进度条使用终端字符实现（沿用现有 `all.py` 风格）。

---

## 4. 配置管理（两种模式通用）

### 4.1 配置来源与优先级

1. 从 `config/config.json` 读取默认值。
2. 用户在配置环节可逐项修改，修改后的值**仅当次运行生效**（不写回 JSON 文件，除非用户主动选择保存）。

### 4.2 可配置参数

| 参数分类 | 参数名 | 说明 | GUI 编辑方式 | CLI 编辑方式 |
|----------|--------|------|-------------|-------------|
| **设备连接** | `host` | 设备 IP 地址 | 文本输入框，预填默认值 | 提示输入，显示默认值，回车使用默认 |
| | `user` | SSH 用户名 | 文本输入框 | 同上 |
| | `pw` | SSH 密码 | 密码输入框（掩码显示） | 同上 |
| **路径配置** | `bin_path` | 远程可执行文件搜索路径 | 文本输入框 | 同上 |
| | `lib_paths` | 远程动态库搜索路径 | 文本输入框 | 同上 |
| | `remote_ota_dir` | 远程固件存放目录 | 文本输入框 | 同上 |
| | `local_image_dir` | 本地固件文件目录 | **文件选择对话框** | 输入路径 |
| **版本校验** | `expected_versions.mcu` | 预期 MCU 版本 | 文本输入框 | 提示输入 |
| | `expected_versions.ufs` | 预期 UFS 版本 | 文本输入框 | 同上 |
| | `expected_versions.switch` | 预期 Switch 版本 | 文本输入框 | 同上 |
| **固件文件** | `firmware_files` | 直接上传模式下的固件文件路径列表，含默认值：`MCU_GTMC_AY5_T1_Merge_Boot_App.hex`, `sail_ota.bin`, `bcm89572_evk_avb_switch_rev1.img`, `ufs_ota.bin` | 每个文件单独的文件选择按钮，预填默认文件名 | 逐个提示输入路径，回车使用默认 |
| | `zip_file` | zip 压缩包路径（选择 zip 时生效） | **文件选择对话框**，过滤 `.zip` 后缀 | 输入路径 |
| | `extracted_files` | zip 解压后预期的固件文件名列表，默认值：`mcu_ota.hex`, `sail_ota.bin`, `switch_ota.img`, `ufs_ota.bin`, `ota_firmware_info.xml`。用户可手动增删。 | 列表编辑器（显示默认列表，可增删改） | 显示默认列表，询问是否修改 |

### 4.3 上传方式判断

**无需用户手动选择上传模式**。脚本根据用户选择的文件类型自动判断：

| 用户选择 | 判定模式 | 行为 |
|----------|----------|------|
| 选择 `.zip` 文件 | **zip 模式** | 上传压缩包 → 远程解压 → 执行升级命令 → 删除解压文件 → 最终删除压缩包 |
| 选择单个固件文件（`.hex` / `.bin` / `.img`） | **direct 模式** | 通过 SFTP 逐个上传至远程目录 → 执行升级命令 |

两种模式适用于所有升级类型（完整升级 + 单独升级 MCU/Switch/SoC）。

### 4.4 配置保存

- 配置确认界面提供 **"保存为默认配置"** 按钮/选项，将当前填写值直接写回 `config/config.json`。
- 保存后下次运行默认值即为上次保存的记录。
- 不点击保存则仅当次运行生效，不修改 JSON 文件。

### 4.5 SSH 连接测试

- GUI 模式的配置窗口提供 **"测试连接"** 按钮，使用当前填写的 host/user/pw 尝试 SSH 连接，成功/失败均给出明确提示。
- CLI 模式提供 `--test-connection` 参数或在配置环节询问"是否测试连接？"。

## 5. 功能需求

### 5.1 升级模式

与现有 `ota_alone.py` 保持一致，支持四种升级操作：

| 序号 | 升级类型 | 说明 |
|------|----------|------|
| 1 | 一键完整升级 | 执行两面（两次）升级，包含 MCU + Switch + SoC |
| 2 | 单独升级 MCU | 仅升级 MCU 固件 |
| 3 | 单独升级 Switch | 仅升级 Switch 固件 |
| 4 | 单独升级 SoC | 仅升级 SoC（sail_ota.bin + ufs_ota.bin） |

### 5.2 固件上传方式

上传方式由用户选择的文件类型**自动判断**（参见 4.3）。

#### 方式 A：直接上传文件（direct）

- 用户通过文件选择器（GUI）或路径输入（CLI）逐个指定固件文件。
- 默认文件列表（以 `ota_alone.py` 中的文件名为准）：
  - `MCU_GTMC_AY5_T1_Merge_Boot_App.hex`
  - `sail_ota.bin`
  - `bcm89572_evk_avb_switch_rev1.img`
  - `ufs_ota.bin`
- 每个文件均可单独修改路径。
- 通过 SFTP 逐个上传至远程目录。

#### 方式 B：压缩包上传（zip）

- 用户选择一个 `.zip` 文件。
- 上传压缩包 → 远程解压 → 执行升级命令 → 删除解压文件 → 最终删除压缩包。
- 解压后的预期固件文件列表有默认值（`mcu_ota.hex`, `sail_ota.bin`, `switch_ota.img`, `ufs_ota.bin`, `ota_firmware_info.xml`），用户可手动增删修改。

### 5.3 升级流程（核心不变）

完整升级流程（与现有脚本一致）：

```
1. SSH 连接设备
2. 上传固件文件/压缩包
3. [zip 模式] 远程解压
4. 执行第一面升级命令序列
5. [zip 模式] 删除解压文件
6. 发送重启命令，等待设备重启
7. 重新 SSH 连接
8. 执行 ota_proxy_app m
9. 版本校验（第一面）
10. [direct 模式] 重新上传文件 / [zip 模式] 再次解压
11. 执行第二面升级命令序列
12. [zip 模式] 删除解压文件
13. 发送重启命令，等待设备重启
14. 重新 SSH 连接
15. 执行 ota_proxy_app m
16. 版本校验（第二面）
17. 环境清理（删除远程固件文件/压缩包）
18. 断开 SSH
```

单独升级 MCU / Switch / SoC 流程与现有 `ota_alone.py` 保持一致。

### 5.4 日志与进度

- **GUI 模式**：沿用现有方案，日志区域 + 状态栏单行进度 + 不确定进度条。
- **CLI 模式**：终端实时输出 + 字符进度条（`█` 风格）。
- 提供 **"清空日志"** 按钮（GUI 模式）。

### 5.5 异常处理

- SSH 连接失败 → 提示错误，不崩溃。
- 命令执行超时 → 提示超时，记录已完成步骤。
- 版本校验不通过 → 明确提示哪个组件不匹配，不中断但告警。
- 重启后无法重连 → 超时重试机制（最多 5 次），失败后提示。

## 6. 非功能需求

| 项目 | 要求 |
|------|------|
| Python 版本 | >= 3.12（解决 TLS 兼容性问题） |
| SSH 库 | paramiko |
| GUI 框架 | tkinter（Python 标准库，无需额外安装） |
| 线程安全 | GUI 模式下升级任务在后台线程执行，UI 操作通过 `root.after()` 回到主线程 |
| 超时控制 | SSH 连接超时 15s，普通命令 300s，压缩包命令 60s |
| 编码 | 全程 UTF-8 |
